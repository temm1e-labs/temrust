**The v0 → v1 → v2 → v3 progression isolated four knobs:**
1. **Format (v0 → v1):** swap diffs → whole-file. Held data and step count constant. Result: −1 point. **Format is not the bottleneck at this data scale.**
2. **Base + steps + data (v1 → v2):** swap base from `Qwen3-1.7B-Base` to `Qwen3-1.7B` (chat), 79 → 176 examples, 9 → 220 gradient steps. Result: **+22 points.** All three changes together produced the breakout win.
3. **More data + more steps (v2 → v3):** 176 → 263 examples, 220 → 330 steps. Same chat base, same hyperparams. Result: **+3 points.** Returns are now diminishing — the linear-data scaling is sublinear.
4. **Issue category is where the model genuinely learned**: 4 → 8/9 (matching the 3B baseline's 9/9). Borrow and type each gained ~1-3 points. Test slightly recovered in v3 (3 → 4) but is still −1 from base — bug-fix training partially overwrites test-generation patterns the chat base had natively.

## Methodology

### Eval harness
- 37 hand-curated Rust tasks across 4 sub-evals: `borrow` (lifetime/move errors, 10 tasks), `issue` (apply diff for documented bug, 9 tasks), `test` (write passing tests for given function, 9 tasks), `type` (type-system / trait errors, 9 tasks).
- All graded by `cargo check`, `cargo test`, or `cargo run` in a fresh tempdir per task. No mocking.
- Inference: OpenAI-compatible chat completions. `max_tokens=8192`, `temperature=0`.
- Extractor: looks for ```rust block in model output. Strips `<think>...</think>` first (Qwen3 thinking models). If `<think>` opens but never closes (truncation), drops it — better to fail compile cleanly than feed thinking-prose to the Rust compiler.

### Training (Tem-Rust v0)
- **Base:** Qwen3-1.7B-Base
- **Method:** LoRA r=16, alpha=32, all-linear modules
- **Data:** 76 SFT examples scaffolded from 124 crawled merged-PR fixes across 34 popular Rust repositories. Format: `{system, user (issue context), assistant (unified diff)}`.
- **Hyper:** 3 epochs, lr=2e-5, cosine schedule, batch_size=32, packing=True, max_seq_length=32768
- **Effective gradient steps:** 9 (= 76 examples ÷ 32 batch × 3 epochs, rounded up)
- **Compute:** Together AI fine-tune API → 143,177 training tokens, ~3 min wall clock
- **Cost:** $4.00 (Together's minimum job charge — actual token cost would have been ~$0.06 at $0.40/Mtok)

### Inference (Tem-Rust v0)
- Together AI dedicated H100 80GB SXM endpoint (`endpoint-32c82312-...`).
- Base-model fine-tunes have **no chat template** — Together's `/v1/chat/completions` echoes the prompt back. We bypass with `/v1/completions` + manual Qwen3 ChatML formatting (`<|im_start|>{role}\n{content}<|im_end|>\n` × N + `<|im_start|>assistant\n`). See `eval/clients.py:TogetherBaseClient`.

### Caveats
- **Format mismatch in v0**: training data uses unified-diff format; eval expects "complete corrected program in a single rust block". This HURTS v0's pass rate vs. the base — model often produces diffs when the eval wants whole files. Future versions will train on whole-file completions extracted from the PR commits.
- **Underfitting**: 76 examples × 3 epochs = 9 gradient steps total at batch_size=32. Far below the threshold for stable instruction-following on a base model. Observed failure modes: (1) echoes input verbatim, (2) drifts into repetitive loop garbage on harder prompts, (3) occasionally produces a coherent diff that doesn't match the eval format.
- **No cargo-verification of training data**: 76 candidates are merged-PR patches (presumed correct because they shipped) but not independently verified to compile + pass tests in a fresh checkout. Phase 1 proper (next 1-2 days) will run cargo verification.
- **Small dataset**: 76 examples × 3 epochs = ~436K training tokens. SFT typically wants thousands of examples. Expect modest behavioral shift, not transformative gains.

## What worked

- **v3 = 54.1% (20/37)** is the strongest 1.7B model on this benchmark. **+19 points over the unmodified Qwen3-1.7B chat (35.1%)**, +2.7 points over Qwen2.5-Coder-1.5B-Instruct (51.4%).
- **v2 was the breakout** (51.4%, first version to beat the base). v3 confirmed the trajectory with another +1 task on 50% more data.
- **The combo of changes mattered, not any single one.** v0 (SFT, base model, 9 steps) → regression. v1 (format fix, otherwise same) → also regression. v2 (chat base, 24× more steps, 2× data) → +16 vs base. v3 (50% more data + steps) → +1 more.
- **3.2× crawler yield improvement** over the v0/v1 crawler: dropped `has_test_addition` hard gate, paginated PR list (5 pages × 100 = 500 PRs/repo), bumped to 100 repos × 30 PRs, broadened stars filter to >300. v3 crawl yielded 396 candidates from ~35 repos before being cut for time.
- Eval harness end-to-end (fresh cargo project per task, supports `[lib]` tasks via `target_file`).
- RunPod launcher hardening — image-pull fast-fail, container-crashloop fast-fail, GraphQL pod state, RunPod-proxy URL discovery, `--max-model-len 16384`, post-launch real-rate cost cap. Failed launches cost ≤$0.05 each.
- Methodology fix for thinking models: strip `<think>...</think>` from output before extracting code; bump `max_tokens` to 8192. Recovered Qwen3-1.7B from 27% → 35%.
- Together AI fine-tune API: tested with both Base and chat variants of Qwen3-1.7B. Chat variant fine-tune is queryable via the standard `/v1/completions` with manual ChatML wrapper just like the Base variant — Together's `/v1/chat/completions` returned 400s on dedicated endpoints regardless.
- Discovery: base-model fine-tunes need a manual chat template via `/v1/completions` (Together's `/v1/chat/completions` route just echoes the prompt back when the underlying tokenizer has no chat template).

## What didn't / open issues

- **Diminishing returns on data scale.** v3 added 50% more data (176 → 263) and 50% more steps (220 → 330) over v2. Result: only +1 task gain (19 → 20). This means the next leap will likely require a *different* signal, not more of the same — synthetic test-generation data, cargo-verified quality gating, or a stronger base model.
- **Test category still slightly regressed** (5 → 4) in v3 vs base. Recovered partially from v2's 3, but the bug-fix corpus doesn't carry test-generation patterns. v4 fix: include test-writing PRs (PRs that *added* a `#[test]` for an existing function) in the SFT mix.
- **Together's dedicated endpoints flap mid-eval** — 8 tasks errored with `dedicated_endpoint_not_running` while autoscaling reported `STARTED|ready=1/1`. Mitigated with retry+backoff in `eval/clients.py:TogetherBaseClient.chat`. Without retries, the first v3 eval run would have undercounted by ~8 points.
- **Together's $4 minimum-job charge** dominated v0–v2 (~$2.40 actual training cost vs $12 paid). v3 finally crossed the floor at $8.50 — bigger datasets are now genuinely paying for training, not sunk cost.
- **No cargo-verification yet** of any PR candidates. The 263 v3 training examples are merge-PR file-pairs — *presumed* correct because they shipped, but not verified to compile + pass tests in a fresh checkout.
- **RunPod RTX 4090 SECURE host pool flakiness**: ~6 of 8 hosts allocated would not boot vllm/vllm-openai:v0.20.1. Workaround: switch to RTX 5090 SECURE.
- **Qwen3-1.7B-Base baseline missing**: chat version covers most of the comparison.

## Next steps (handoff)

v3 = 54.1% — strongest 1.7B on the benchmark, but the 19-point gap to the 3B bar (73.0%) is unlikely to close from more crawled bug-fix data alone (v2→v3 only gained +1 task on +50% data). The next leap needs *different* data:

1. **Synthetic test-generation slice.** Use Qwen3-Coder-Next-FP8 (teacher, serverless, $0.50/Mtok) to generate "write tests for this function" examples. Mix into SFT at ~20-30% ratio. Direct attack on the −1 test-category gap.
2. **Targeted borrow-checker / lifetime data.** Mine rustc UI tests + curated Rust-by-Example for {broken, fixed} pairs around lifetimes/borrows. v3's borrow stayed at 4/10 — the bug-fix corpus is undersampled in pure borrow-checker fixes.
3. **Cargo-verify the training data.** Clone repo at base_sha, apply patch, `cargo check` + `cargo test`. Drops broken/no-op examples and raises signal-per-token. Time: 6+ hours wall clock but mostly free compute.
4. **Bigger base** if available. Qwen2.5-Coder-3B-Instruct starts at 73.0% — fine-tuning it should push past 80%. Currently not a Together fine-tune base, but RunPod DIY fine-tune is feasible.
5. **More raw data** still helps but with diminishing returns. The v3 crawler (`scripts/crawl_rust_issues_v2.py`) was killed at repo ~35/100 — finishing the run is free and might add 200-300 more candidates, but expect just another +1-2 tasks.
6. **RunPod-hosted DIY fine-tune** to escape the $4 minimum-charge floor for sub-experiments (LR sweeps, LoRA rank ablations).
7. Add MultiPL-E Rust + RustEvo² + Aider Polyglot for broader external benchmark coverage.
8. Run baseline for Strand-Rust-Coder-14B (reference upper bound; needs RTX 4090+ for VRAM).
9. ✅ **Stopped all four dedicated endpoints** at end of this session — v0 ran 13.7 min, v1 ran 11.7 min, v2 ran 5.2 min, v3 ran 10.7 min.
