# v7 Plan — Agentic Rust at 3-4B (theorized, not yet executed)

**Status:** drafted 2026-05-06 evening, not yet started. v5 (TemRust-SMOL-v5-1.5B at 67.6%) is the current published model. v6 IQmax was tested and not released. This document captures the next-experiment plan for resumption.

**Goal:** train an agentic-coding-specialized Rust model in the 3-4B parameter range that beats v5 (67.6%), beats the untrained 3B Coder base (73.0%), and additionally learns multi-turn tool-use behavior absent from v5.

## 2. Recommended primary + alt

**v7-A (primary): Qwen2.5-Coder-3B-Instruct.** Same family that drove v5's +13.5pp lift. **Untrained baseline already 73.0%, already beats v5's 67.6% before any fine-tuning.** Doubling on the proven Coder lever is the highest-EV move. Plausible v7-A final: **80-85%**.

**v7-B (alt): Qwen3.5-4B.** Tests "newer-generation general > older-generation Coder" hypothesis. +33% params over v7-A. If Qwen3 paper's claim transfers, baseline could be 65-72%; with SFT plausible 75-85%. **Unknown until baselined; that's the experiment.**

**v7-C (research bet, optional): Gemma 4 4B.** Released May 2026, built explicitly for agentic workflows, builtin tool-calling. Different tokenizer (128K context, multimodal-aware). High variance — could be either 50% baseline or 70%. Run only if v7-A and v7-B are budget-comfortable.

## 3. Data plan

The v5 corpus is fix-this-file shaped only. To unlock **agentic** behavior we need multi-turn tool-use traces. Three slices:

### Slice 1 — keep v5's 355 rows
- 263 real PR-fix file pairs (v3 crawler output)
- 51 borrow/lifetime archetypes (teacher-fixed)
- 41 teacher-distilled test scaffolds
- Already cargo-verified-ish, already proven to lift the base

### Slice 2 — NEW: cargo-grounded agentic traces, ~200 rows
For each of 200 PRs from the **remaining unused crawler output**, synthesize a multi-turn trace where:

- **System:** "You are a Rust agent with tools: `read_file`, `write_file`, `cargo_check`, `cargo_test`, `grep`. Call tools as `<tool>arg</tool>` blocks; you receive results in `<tool_result>...</tool_result>`."
- **User:** real GitHub issue text from the PR
- **Assistant turns:**
  1. read_file the relevant file
  2. grep / read_file related files
  3. propose patch
  4. write_file the patch
  5. cargo_check
  6. (if fail) revise + repeat 4-5
  7. cargo_test if applicable
  8. final summary

The crucial property: **every `<tool_result>` is real cargo/shell output**, generated by *actually running the proposed patch* against the cloned repo at base_sha. Not teacher hallucination.

This requires a new script: `scripts/synth_agentic_traces.py`. Pseudo:
```
for pr in unused_prs[:200]:
    repo = clone(pr.repo, pr.base_sha)
    issue = pr.title + pr.body
    transcript = teacher.generate_initial_plan(system, issue)
    for step in transcript.tool_calls:
        if step.tool == "read_file":
            result = repo.read(step.arg)
        elif step.tool == "cargo_check":
            result = run_cargo_check(repo)
        elif step.tool == "write_file":
            repo.write(step.path, step.content)
            result = "ok"
        # ...
        transcript.append(tool_result(result))
        if final: break
        next_action = teacher.continue(transcript + tool_result)
        transcript.append(next_action)
    if final.cargo_check_passes:
        save(transcript)
```

Estimated yield: 50-70% of 200 attempts produce a passing trace = **100-140 rows**.

### Slice 3 — NEW: rustdoc Q&A, ~100 rows
Doc-grounded mini Q&A. For each rustdoc page (std::collections, tokio, serde, anyhow, thiserror, async-trait, rayon):
- User: "How do I X with Y?" or "What does this signature mean?"
- Assistant: doc-grounded answer with a small Rust code example.

Source: scrape rustdoc HTML, feed sections to teacher, generate Q&A grounded in the actual doc text.

## 4. Training math

### Compute scaling for 3B vs 1.5B

Per-step FLOPs ∝ params. Per-token wall-clock on H100 for a 1.5B w/ packing+grad-ckpt+bf16:
- v5: ~2s/step × 570 steps = ~19 min training

For 3B (2× params):
- ~4s/step × ~700 steps (slightly larger corpus) = **~47 min training**
- Cost: 47 × $3.49/60 = $2.74/run

For 4B (2.7× params):
- ~5.5s/step × ~700 steps = **~64 min training**
- Cost: 64 × $3.49/60 = $3.72/run

### Memory at 3-4B with our config

- 3B bf16 weights: 6 GB
- LoRA r=64 α=128 trainable params: ~50M × 4 bytes (fp32 master) = 200 MB
- Adam optimizer state: ~50M × 8 bytes = 400 MB
- Activations w/ grad ckpt + packing seq=4096 batch=4: ~30-40 GB
- **Total: ~40 GB on H100 80GB. Fits with ~2x headroom.** Could increase batch to 8 (drop grad_accum to 1) for slightly better throughput.

For 4B: ~50 GB peak. Still fits.

### Variance management

v5 taught σ ≈ 2.8 task per-run noise. **Assume this for every base.** Always run **3 retrains in parallel** and publish the best of 3.

Cost per base: 3 × $2.74 (3B) = $8.22, or 3 × $3.72 (4B) = $11.16. Add eval (~$0.30 each × 3 = $0.90).

### Data scaling

Pretraining is fixed (we inherit it). For SFT, empirical rule for instruction-tuning a *Coder*-pretrained model: **0.1-1% of pretraining tokens, OR enough to expose every behavior 5-10 times.** We want ~600 examples × 10 epochs = 6,000 exposures, which puts every behavior pattern (borrow fix, type fix, agentic plan-act loop, doc Q&A) at well above the 5-10× lower bound assuming we have ~50 distinct patterns.

**Hypothesis-relevant specifically**: agentic behavior appears at ≥150 multi-turn traces in published work (DeepSeek-R1 distill recipe, Anthropic tool-use SFT). We're at 100-140. Probably enough; if v7 underdelivers on agentic, double slice 2 to 250-300.

## 5. Step-by-step plan

### Phase 0 — baseline new bases (~$3, 30 min)
1. Spin up RunPod H100, deploy Qwen3.5-4B and Gemma 4 4B sequentially via vllm
2. Run our existing 37-task eval against each (no fine-tune, just untrained baseline)
3. Compare to v5 retrain #2's 25/37 = 67.6%
4. Decision gate:
   - If Qwen3.5-4B baseline ≥ 60%: continue to v7-B
   - If Gemma 4 4B baseline ≥ 60%: continue to v7-C  
   - If both <55%: skip v7-B/C, pour budget into v7-A retrains
5. Stop pod

### Phase 1 — data (~3-5 hours wall, ~$3-5)
1. Write `scripts/synth_agentic_traces.py` — clone repo, run cargo, log multi-turn trace
2. Write `scripts/synth_rustdoc_qa.py` — scrape rustdoc, generate Q&A
3. Run both with parallel teacher workers (6× concurrency, learned from v6 synth)
4. Cargo-verify agentic traces; drop failures
5. Combine into `data/clean/sft_v7_agentic.jsonl`
6. Commit + push

### Phase 2 — train (~$22 if both v7-A and v7-B, ~$11 if just v7-A, parallel pods, 50-60 min wall)
1. Modify `scripts/train_coder.py` to accept `--base` arg cleanly (already done)
2. Write `scripts/runpod_train_coder_v7.py` derived from v6 launcher with:
   - `--base Qwen/Qwen2.5-Coder-3B-Instruct` for v7-A
   - `--base Qwen/Qwen3.5-4B` for v7-B
   - LoRA r=64 α=128 (more capacity for bigger base)
   - lr=1e-5 (slower for larger LoRA)
   - 10 epochs, packing=True, max_seq_len=4096
3. Launch 3 parallel pods per base = 6 pods total
4. Embedded log server on each (proven from v5/v6)

### Phase 3 — eval + release (~$2)
1. Run 37-task eval against all 6 retrains
2. Pick best of 3 per base
3. Compare:
   - v7-A best vs v5 (25/37 = 67.6%)
   - v7-A best vs untrained Coder-3B (27/37 = 73.0%)
   - v7-B best vs v7-A best
4. Release decision:
   - If best v7-A ≥ 28: publish as `TemRust-SMOL-v7-3B`
   - If best v7-B > best v7-A: publish v7-B as `TemRust-Qwen3.5-4B-Tem-Rust`, keep v7-A as alt
   - If neither beats 25: document, don't publish, fall back to v5

### Phase 4 — agentic eval (optional, ~$0)
1. Build a tiny 5-task agentic benchmark using existing PR fixes:
   - Provide read/write/cargo_check tool stubs locally
   - Each task: "fix this issue, you have these tools"
   - Score: cargo_check passes after final state
2. Run against v5 (1.5B) and v7 retrains
3. Document the agentic-specific lift in research_paper.md

## 7. Open questions to resolve before starting

1. **Agentic eval format.** What exactly does a tool-call trace look like in our SFT? OpenAI function-call JSON? XML tags? Plain text "Tool: cargo_check"? The choice locks the inference-time format and changes how the model is prompted at eval. Recommend: XML tags (`<read_file>path</read_file>`) — simple to parse, robust, doesn't require structured-output decoding.

2. **Rustdoc scraping target.** Which crates? Recommend: std + tokio + serde + anyhow + thiserror + async-trait + rayon + clap + reqwest. Each ~10 Q&A = 80-100 rows.

3. **Teacher choice for agentic.** Qwen3-Coder-Next-FP8 (used for v6, $0.85/Mtok blended, strong code) or DeepSeek-V3.1 (frontier reasoning, $0.60-1.70). Recommend: **mix** — Qwen3-Coder for the actual tool-call decisions (better Rust knowledge), DeepSeek for plan-step reasoning where applicable.

4. **Multi-base training in parallel.** 6 H100 pods running simultaneously is fine on RunPod (they're independent). Verify there's no per-account concurrent-pod limit.
